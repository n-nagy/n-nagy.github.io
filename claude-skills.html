Skills in Cowork — What They Are, How to Use Them, How to Build Them

This is the practical guide to skills in Claude Cowork. If you're wondering "I've heard about skills — what do I actually do with them?" — this is the doc.

For the conceptual framing on how to think about what makes a good skill, read Building your first skill or automation first. This doc picks up from there and walks through the mechanics.

What is a skill?

A skill is a set of instructions that tells Claude how to do a specific task. Think of it like a really good Standard Operating Procedure (SOP) — except instead of handing it to a new hire, you're handing it to Claude.

When you open Cowork and ask Claude to do something that matches a skill, Claude follows those instructions instead of improvising. That's it. Skills make Claude more reliable, more consistent, and better at the specific things your team actually does.

Skills live as files inside your Cowork setup. They're not magic. They're just well-written instructions with context about what tools to use, what to look at, and what the output should look like.

How do I use a skill?

You don't need to do anything special. If a skill is installed in your Cowork environment, Claude will automatically use it when your request matches what the skill is designed to do.

For example, if you have a "weekly program review" skill installed and you say "write this week's program review," Claude recognizes that it has a skill for that and follows the instructions.

You can also trigger a skill explicitly by typing / followed by the skill name — like /skill-name. This is useful when you want to make sure Claude uses a specific skill rather than its general knowledge.

Where to find your installed skills: Open Cowork and go to Customize → Skills. You'll see a list of what's available. Each skill has a name and a short description of what it does.

How do I build a skill?

Building a skill is more accessible than you might think. You don't need to write code. You need to write clear instructions.

The quick version

  1. Start a Cowork session and tell Claude: "I want to create a new skill."
  1. Claude will walk you through it using the skill creator — it'll ask you what the skill should do, what tools it needs, and what good output looks like.
  1. You describe the task in plain language. Be specific: what inputs does the skill need? What should it look at? What should the output look like? What are the edge cases?
  1. Claude generates the skill file for you. You can test it, iterate on it, and refine it until it works the way you want.

What makes a good skill

  • Specificity over generality. A skill that does one thing well beats a skill that tries to do five things. "Draft a follow-up email for an AE after a Gong call" is better than "help with sales emails."
  • Clear decision logic. Claude needs to know how to make judgment calls. Don't just say "prioritize the important ones" — say what makes something important in your context.
  • Real examples. Include before/after examples of what good output looks like. This is the single most effective thing you can do to improve a skill.
  • Specify the tools. If the skill needs to pull from Salesforce, search Slack, or write to Notion — say so explicitly. Claude has connectors to these tools but needs to know when to use them.

Tips from experience

  • Start small. Get the basic loop working before adding complexity. You can always add edge case handling later.
  • Test with real data. Don't just test with a toy example — run it against actual work and see if the output is something you'd actually use.
  • Iterate with Claude. If the output isn't right, tell Claude what's wrong. "The tone is too formal" or "you're missing the deal stage from Salesforce" — Claude can update the skill in the same session.
  • Use the skill creator. Seriously. It handles the file structure and formatting for you so you can focus on the content. Just say "I want to create a skill" or type /skill-creator.

How do I share a skill?

This is where it gets fun. Skills aren't useful if they live in one person's Cowork setup — the whole point is that good workflows spread.

Share with your team

The simplest way: export your skill and share the file with teammates who can install it in their own Cowork environment. Your DRI can help coordinate this for your department.

Share with the company

Next to your skill, there’s a Share button where you can share it to the entire company. We highly encourage doing this! This will make it available for others to install under “Shared Skills”. Then, post it in #adaptive-uses-ai — this is the channel for sharing wins, workflows, and skills across Adaptive. When you share, describe what it does, who it’s useful for, and an example of the output. This helps other people figure out if it's relevant to them without having to install it first.

Request it be added to the org plugin

If you've built a skill that works well and would be useful to auto-install for a specific team, ping the AI Enablement team or drop a note in #bet-ai-enablement. We can add it to the right org plugin so it's available to by default.

FAQ

Do I need to be technical to build a skill?

No. If you can describe a workflow clearly enough to explain it to a new teammate, you can build a skill. The skill creator handles the technical parts.

Can a skill break anything?

Skills can read from and write to your connected tools (Slack, Notion, etc.), so use the same judgment you'd use with any automation — start with read-only actions and add write actions once you're confident in the output.

What if my skill isn't working right?

Iterate on it in a Cowork session. Tell Claude what's wrong and it'll update the instructions. If you're stuck, bring it to office hours (Wednesdays 2-3pm ET) or ask in #bet-ai-enablement.

What's the difference between a skill and a scheduled task?

A skill runs when you (or someone) triggers it. A scheduled task is a skill that runs automatically on a schedule — every morning, every Friday, every hour. If there's a predictable moment when the skill should run, set it up as a scheduled task.
