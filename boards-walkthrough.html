The big idea

What Boards Are

A Board is a reusable reporting package. Instead of sending people across many report pages, it gathers the right report snapshots, explains what changed, and packages the result for sharing.

1

Curated reporting

Each Board contains report tiles selected for a specific business moment or audience.

2

AI analysis

The summary looks across the Board's reports and turns data patterns into concise takeaways.

3

Shareable output

The same Board can be viewed in the product or exported as a PowerPoint briefing.

Parts that came together

Boards combine reusable reporting primitives with a few targeted new pieces

The feature is less about one giant new system and more about composition. Boards sit on top of existing reporting, filtering, visualization, saved-view, and analytics infrastructure.

ClickHouse infrastructure

Low-latency analytics infrastructure gives reporting a fast foundation for event and metric data.

Reporting engineering effort - August 2025

Option A

Postgres flattened tables

4-6 weeks

Highest confidence and lowest extra cost, but more rigid as reporting grows and joins become more complex.

Option B

ClickHouse

5-7 weeks

Medium-high confidence with Kafka-to-ClickHouse wiring, materialized views, and a better fit for low-latency analytics.

Option C

Redshift

6-8 weeks

Good scale, but slower iteration, heavier AWS service dependencies, and higher modeled monthly cost.

The takeaway: ClickHouse was the balanced infrastructure bet. It cost more than staying in Postgres, but gave reporting stronger scale, lower-latency analytics, and more future flexibility than the Redshift path.

Customer workflow

The user journey

From a user's point of view, Boards feel like a guided workflow: choose the starting point, tailor the reporting, generate the narrative, and share the finished package.

1

Choose a starting point

Managed templates live as library_report_boards. Users can preview a template against their real data, then fork it into a customer-owned company_report_boards record, or create that company Board directly from scratch.

2

Manage Board context

Add, remove, and reorder tiles tracked in report_board_tiles. Each tile points back to a reporting library option and carries saved display context, giving the Board an ordered set of reports for rendering, AI, and export.

3

Tune the scope

Tile order is stored in report_board_tiles.sequence, while most tile-specific settings live in the details JSONB column: filters, date range, display mode, hidden columns, and chart/table visibility. That saved scope is reused for rendering, AI context, and export.

4

Regeneration marks the summary tile as generating and starts ReportBoardSummary with the company, Board prompt, selected tiles, date range, and report-query tools. Generated markdown is saved back onto the Board.

My stamp on the product

The AI summary is an analyst workflow, not just a prompt

I created, tested, and iterated on the prompt structure to produce high-quality summaries via an agentic workflow builder.

AI Summary Scaffolding

The AI summary is backed by a shared Adaptive workflow called ReportBoardSummary. It combines a reusable system prompt, board-specific context, GPT-5.4, and report-query tools so the output is grounded in the Board's actual data.

Board prompt and context

Input includes company, Board, date range, selected report views, tile names, current date, and the summary prompt already stored on the Board. Users can customize that prompt, but they do not need to write one from scratch.

AI investigates reports

Tools like list_available_reports, get_report_filters, and get_report let the model inspect report data instead of guessing.

Result is persisted

The generated markdown, completion status, and timestamp are saved back into report_board_tiles for the UI and exports.

  • Use the available report tools for evidence.
  • Prioritize meaningful deltas and risks.
  • Write in a concise executive style.

What the UI needs to handle

  • Show generating state on the summary tile.
  • Poll the Board until status changes.
  • Let users regenerate after report or date changes.
  • Keep the saved summary available for export.

Why this matters

The AI is not just rewriting visible charts. It gets a structured brief about the Board, receives a common instruction set, and can call report tools to find evidence-backed patterns.

  • Shared prompt keeps tone and structure consistent.
  • Board context keeps each run customer- and date-specific.
  • Report tools ground conclusions in current metrics.
  • Saved tile status makes the async experience reliable.

Prompt appendix

The full prompts behind the AI summary

The workflow has a shared system prompt, then wraps the Board-specific prompt value as user instructions. The template prompts below are the seeded defaults for common Board starting points.

Default workflow system prompt Shared instructions used across ReportBoardSummary runs 
You are a security officer responsible for generating content as specified below.

You have several tools available to you:
- list_available_reports will give you all reports that are available, including descriptions of their
data, use cases, and available dimensions (group by clauses)
- get_report_filters will give you the filters available for a given report. Be sure to always call
this before calling get_report
- get_report will get the actual data for a report given some set of filters and dimensions.

MANDATORY ANALYSIS METHOD (SEQUENTIAL)

TOOL-CALL EXECUTION STRATEGY
- Use sequential calls only when the next call requires outputs from the previous call.
- When calls are independent, issue multiple tool calls in the same iteration.
- Prefer batching independent calls to maximize insights within the iteration budget.
- Typical batching opportunities:
  * After Discover: fetch get_report_filters for all selected report types in one iteration.
  * Baseline: run multiple top-level get_report calls (for different report types) in one iteration.
  * Validation: run multiple cross-check get_report calls in one iteration when they do not depend
  on each other.

1) Discover:
- Call list_available_reports once at the beginning.
- Choose the reports most relevant to the board objective.

2) Set Time Windows:
- Use a trailing period window ending today for the primary analysis.
- Use the preceding period window as the comparison baseline.
- Use explicit startDate and endDate in every get_report call.

3) Build Baseline:
- For each selected report type, call get_report_filters first.
- Then call get_report at high level (NO_DIMENSION or top-level dimension) to establish baseline trends.
- If multiple baseline queries are independent, call them together in the same iteration.

4) Detect High-Signal Patterns:
- Identify materially shifted metrics, inflection points, and concentration pockets.
- Focus on patterns with meaningful business impact, not noise.

5) Progressive Drill-Down:
- Drill down one level at a time, where each next query depends on the previous result.
- Preferred granularity ladder: organization-wide -> department/division/location/manager/group ->
campaign/scenario/attack-vector/sender.
- If risk is high in one segment, isolate likely drivers through additional dimensions and filters.
- For multiple independent segments/hypotheses, evaluate them in parallel within the same iteration.

6) Hypothesis + Validation:
- For each candidate insight, form a clear hypothesis and test it with dependent follow-up queries.
- Validate each insight with at least one cross-check from a second report type or alternate dimension.
- Guard against denominator effects by checking simulation volume/cadence and audience size context.

7) Synthesize:
- Output only evidence-backed insights.
- Final summary must contain at least 3 high-confidence patterns. If fewer are supportable, explain
why and describe what was checked.
- Each reported pattern must be backed by at least two tool results and one cross-check.
- If data is insufficient, explicitly say what was checked and what limits confidence.

QUERY RULES
- Never call get_report before get_report_filters for that report type.
- Every get_report call must include reportType, dimension, startDate, endDate, filters, page, and
pageSize.
- In every iteration, emit as many independent tool calls as useful; avoid single-call turns unless
the workflow is strictly dependency-bound.
- Use focused query chains over many shallow queries.
- Do not finalize early. Complete the full sequence before producing the final summary.

You can use dimensions and filters to drill down into data. For example, if a department has
high risk, change the dimension to EMPLOYEE and use the department as a filter.

You only have 15 tool call iterations to complete the summary. Be strategic about each iteration
and do not be too verbose. You should complete this within 60 seconds.

Round all values to 2 decimal places.

The report board's time range is: {{time_range}}.
Use this time range for your primary analysis window when calling get_report.

CROSS-CUTTING RULES
Always compare to the prior period with a number and a delta. Never describe a trend without quantifying it.
If the data contains an explicit reason for a metric movement, include it in one sentence. Do not speculate beyond what the data supports.
Lead with the theme, not the metric. Group related signals into a narrative thread rather than walking through charts one by one.
Stay lean. The full summary should be readable in under 60 seconds. Skip metrics that are stable and unremarkable.
No filler. Start with the finding. End when you're done.
After drafting, remove any sentence that restates something already said in a bullet. Each sentence and bullet must add new information or it gets cut.

DATE FORMATTING
Never use ISO format (YYYY-MM-DD). Always write "Month D, YYYY".
Weave the reporting period into prose naturally — never as a standalone label or header.

NUMBER FORMATTING
Bold a maximum of 3-4 numbers per summary — the most important ones only.
Never chain more than two numbers in a single clause.
Prefer percentage form over raw fractions. Omit fractions unless essential.
Never write "about" before a number. Round to one decimal place instead.

SIGNAL DISCIPLINE
Pick one time frame for comparisons and stick to it. Do not mix period-over-period with within-period breakdowns.
If two data points about the same metric conflict, pick the more actionable one. If both are essential, give each its own bullet and explain the tension plainly.
If a rate changed because volume changed, lead with the volume shift as the explanation — not as a parenthetical caveat.
Name at most two segments: the worst performer and, only if meaningfully different, the best. A segment may be a department, team, role, campaign, policy, or any other breakdown in the data.
Never narrate your own analysis. State findings directly.

DATA HYGIENE
Omit records that appear to be test, demo, or internal artifacts (e.g. names containing "Test", "Copy", "Demo") without comment.
Never explain what you excluded or why.

CONCISION:
After drafting, remove any sentence that restates something already said in a bullet. Each sentence and bullet must add new information or it gets cut.

STRUCTURE Follow this shape exactly, in this order:
**HEADLINE**
One sentence in bold.
Capture the key tension — if something improved and something worsened, name both.
Title case, under 15 words.
Must be specific to this period.
Good: "Phishing Resilience Holds, But Engineering Remediation Backlog Keeps Growing"
Bad: "Mixed Results This Quarter"
3-5 bullets covering the most material findings — program-level metrics and the biggest risk segment together.

Example:
    Reporting Rate Improves, But Fail Rate and Engineering Backlog Both Rose
    Phishing fail rate rose to 5.8% from 5.1% last quarter (+0.7 pts), above the industry benchmark
    Reporting rate improved to 2.6% from 2.0% — the one metric moving in the right direction
    Risk score eased to 32.7 from 34.1 (-1.4 pts)
    Engineering is the clearest gap: fail rate climbed to 8.5% from 6.7%, with 48 overdue assignments up from 42

Key Challenge

PowerPoint export packages the Board for executive workflows

Export was on the critical path to a complete value prop, but it was quickly becoming the highest level of effort on the project. Every format we evaluated — multi-tab XLSX, PDF, Google Slides — came with its own rendering, fidelity, or integration challenges.

Challenge

1Choosing the export format

The export needed to support a full Board narrative rather than isolated charts. XLSX worked well for raw data exploration, but not executive storytelling. Google Slides added collaboration benefits, but PowerPoint aligned best with how security leadership teams already present updates.

Challenge

2Preserving Board fidelity

The exported deck needed to maintain layout integrity, chart styling, typography hierarchy, summary formatting, spacing, branding consistency, and predictable rendering across PowerPoint versions while still handling async generation, asset loading, and large Board payloads reliably.

Solution we landed on

Export is handled as a background job and built with Apache POI, the open source library used for creating Microsoft Office documents programmatically.

1

User clicks export

The UI asks for a PowerPoint version of the Board.

2

Job starts

The system immediately returns a download job so the user is not blocked.

3

Slides are built

Summary content and report charts are collected and laid out with Apache POI's PowerPoint APIs.

4

File is delivered

The finished PowerPoint is uploaded and appears in the user's download queue.

What exports well

  • ✓Executive summary slides.
  • ✓Report charts using the Board's saved filters and dates.
  • ✓Links back to the Board and specific tiles for follow-up.

What to call out

  • ✓Export is asynchronous, so users can continue working.
  • ✓The Board remains the source of truth after the file is created.
  • ✓Tables are visible in-app; export focuses on charts and summaries.

Additional Challenges / Takeaway

What building Boards taught us

Boards look simple because the user experience is intentionally packaged. Underneath, the hard parts were making reused reporting pieces behave consistently across editing, AI analysis, and export.

1Reuse needs strong contracts

Reporting primitives were a big advantage, but Boards forced them to work together in one durable package. Saved report views, filters, dates, charts, and table settings all had to mean the same thing in the editor, the AI workflow, and export.

2Async work needs visible states

Summary generation and PowerPoint export are background jobs, so the product has to make progress, freshness, and completion obvious. Polling, generating states, and download status are part of the core experience, not just implementation details.

3Export is a product surface

A PowerPoint export is not just file generation. It has to preserve the Board narrative, respect saved scope, choose slide-friendly representations, and still point people back to the live source of truth.

Post-launch review

Learning and Impact

DB data: Apr 13 – May 19, 2026  ·  RUM data: Apr 21 – May 19, 2026  ·  Active companies only

Exec Boards launched to strong top-of-funnel interest — 518 companies explored at least one template in the first five weeks. The funnel narrowed sharply initially at each step: roughly 1 in 10 template viewers went on to create a board. We've improved parts of the experience, including the UX of entering edit mode, and now 30% of companies have a custom board while more than half of companies view the Boards page each week. Qualitative feedback has also been encouraging: teams report meaningful time savings in executive reporting and are excited for additional templates tied to future product launches.

✓ What's working

  • Strong template discovery — CISO Review, Leadership Update, and Audit Preparedness each reached 276–327 companies
  • AI summary generation is healthy: 99.4% completion rate across 177 generations
  • Users who do create boards show meaningful customization: 33% of tiles are novel, not copied from library templates
  • Multi-board use case emerging — one enterprise customer built 8 country-specific boards for regional reporting

⚠ Where to dig in

  • Post-creation editing is minimal. Insight to validate: Are customers happy with base templates or still find the customization challenging?
  • Exports remain relatively low — PowerPoint is currently the only whole-board export format, while schedule/send, board-level filters, trends over time, and PDF export were all deferred despite being the features most likely to drive recurring workflow adoption.
